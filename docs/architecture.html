Factory Inventory Management System

Architecture overview: a Vue 3 single-page app over a FastAPI service backed by in-memory JSON data.

Three tiers with no database. The browser calls the API directly; the API reads from lists loaded once at startup.

Data flow

How a filter change becomes a re-rendered chart.

  1. User changes a filterFilterBar updates the singleton refs in useFilters (period, location, category, status), shared by every view.
  2. View builds a filter objectgetCurrentFilters() maps period to month and location to warehouse.
  3. api.js sends the requestBuilds the query string and drops any filter equal to 'all'.
  4. FastAPI filters in memoryapply_filters and filter_by_month run over the lists loaded from JSON; month accepts a month or a quarter.
  5. Pydantic validates the responseTyped models serialize inventory, orders, demand and backlog; summary and report endpoints return computed dicts.
  6. Vue re-rendersRaw results sit in refs (allOrders, inventoryItems); derived values are computed properties.

Things to know

No persistence

Data is read-only mock JSON loaded at import. Restarting the server reloads it; inventory has no time dimension, so it ignores month.

Hardcoded API URL

api.js targets http://localhost:8001/api directly; there is no Vite proxy or environment configuration.

Gap found: api.js defines task and purchase-order calls (/api/tasks, /api/purchase-orders), but server/main.py has no matching routes yet, and /api/backlog is the only purchase-order-aware endpoint. Those calls will return 404 until the backend routes are added.
